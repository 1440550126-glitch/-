# SUNO 批量挂机 · 本地验收清单

这份清单帮你在**自己电脑上**一步步把工具跑通、校准选择器。按顺序做，每步给了「通过标准」和「不通过怎么办」。
关键点：**先小样验证再放量、先 dry-run 再真生成、选择器失效有固定套路修**。

> 环境要求：Node.js ≥ 20（建议 22）。这个工具依赖真实浏览器 + 你的 SUNO 账号，容器/CI 里跑不了，必须本机跑。

---

## 阶段 0 · 装好环境

```bash
cd suno-batch
npm install
npx playwright install chromium
cp .env.example .env
cp tasks.example.csv tasks.csv
```

- **通过标准**：`npm run check` 输出 `OK`；`.env` 和 `tasks.csv` 已生成。
- **不通过**：
  - `playwright` 装不上 → 网络问题，重试 `npx playwright install chromium`。
  - Node 版本低 → 升级到 20+（`node -v` 确认）。

编辑 `.env`：至少填 `LLM_API_KEY`（复用你主项目的火山方舟/DeepSeek/OpenAI key）。`LLM_BASE_URL`、`LLM_MODEL_DEFAULT` 按你的厂商填。

---

## 阶段 1 · 大模型内容生成（不碰浏览器，最先验）

```bash
npm run gen
```

- **做什么**：只调大模型，把每首歌的 歌名/曲风/歌词 生成并写到 `var/results.jsonl`，不开浏览器。
- **通过标准**：终端逐条打印 `📝 歌名 | 曲风`；打开 `var/results.jsonl` 看歌词，应有 `[Verse] [Chorus]` 结构标签、曲风是英文术语、双语行（第 2 首 `赛博朋克…` 设了 `双语`）主歌中文副歌英文。
- **不通过**：
  - 报「缺少 LLM_API_KEY」→ `.env` 没填对，或 `LLM_BASE_URL` 结尾多了 `/`（代码会自动去掉，但确认 key 有效）。
  - HTTP 401/403 → key 错或没权限；HTTP 404 → `LLM_BASE_URL` 路径不对（该指到 `/v1` 或 `/api/v3` 这一层，代码会自己接 `/chat/completions`）。
  - 歌词没有结构标签 → 换个更强的模型（`LLM_MODEL_DEFAULT`），或看 `references/suno-lyric-standard.md` 确认预期。

> 验完可删 `var/results.jsonl` 重来（否则后面会跳过这些已生成的）。

---

## 阶段 2 · 登录 SUNO（一次性）

```bash
npm run login
```

- **通过标准**：弹出浏览器 → 你手动登录 suno.com → 终端显示 `✅ 登录成功`。之后 `.suno-profile/` 目录保存了登录态。
- **不通过**：
  - 一直停在登录页 → 确认你真的登录进了 suno.com 的创作页；5 分钟超时会退出，重跑即可。
  - 浏览器没弹出来 → `.env` 里 `HEADLESS=false`（默认就是）。

---

## 阶段 3 · 选择器校准（最关键，SUNO 会改版）

```bash
npm run dry
```

- **做什么**：真开浏览器、真填 歌词/曲风/歌名，但**不点生成**。用来验证脚本能不能找到并填对那三个输入框。
- **通过标准**：浏览器里能看到三个框被自动填上内容；终端每首打印 `✓ 已填表（dry-run，未生成）`，没有「找不到 xxx 输入框」的报错。
- **不通过（找不到输入框）**——固定修法：
  1. 跑 `npm run inspect`，浏览器停在创作页。
  2. 右键那个填不进去的框 → 检查，看它的 `placeholder` 或 `aria-label`。
  3. 打开 `config.json`，在对应字段（`lyrics`/`style`/`title`/`createButton`）的候选数组**最前面**加一条，例如：
     ```json
     "lyrics": ["textarea[placeholder*=\"你看到的真实 placeholder\" i]", ... 原有的 ...]
     ```
  4. 重跑 `npm run dry` 直到全绿。

> 记住：`config.json` 每个字段是「一组候选，从上往下试，命中即用」。你只需把当前 SUNO 页面对的那条加到最前面，不用删旧的。

## 阶段 4 · 真生成 1~2 首（小样）

先把 `tasks.csv` 删到只留 1~2 行，然后：

```bash
npm start
```

- **通过标准**：浏览器自动填表 → 点生成 → 终端 `✅ 已提交生成`，SUNO 里能看到新歌在生成。热键 `p` 能暂停、`s` 跳过等待、`q` 退出。
- **不通过**：
  - 点了生成没反应/报「找不到生成按钮」→ 回阶段 3 修 `createButton` 选择器。
  - 提示额度不足 → 正常，说明检测生效；充值或换阶段 6 的多账号。
  - 判定「未确认提交」→ SUNO 的成功提示文案变了，去 `config.json` 的 `errorToast`/加一条成功特征；或先忽略（歌其实已在生成）。

验通过后再把 `tasks.csv` 放回全量。

## 阶段 5 · 下载 + 质量回捞

```bash
npm start -- --download --quality
```

- **通过标准**：
  - 生成的歌陆续下载到 `var/downloads/<歌单>/*.mp3`，清单在 `var/downloads.jsonl`。
  - 结束时打印 `🔎 质量回捞：合格 N · 重排 M`；跑坏（时长过短）的会在 `var/results.jsonl` 里被标 `error`，下次 `npm run retry` 会重生成。
- **不通过（下载不到）**：SUNO 的音频接口形态变了，属 best-effort 失效，**不影响生成**。可退回手动在 SUNO 资料库下载；或抓一下生成时的网络请求，看哪个接口返回了 `audio_url`，据此微调 `harvest.js` 的过滤条件（`/suno|clip|feed|generate|song/i` 那行）。
  - 质检「未捕获」很多 → 同上，没抓到 clip 元数据；确认 `--download` 开着（质检依赖 harvest 抓到的时长）。

## 阶段 6 · 多账号轮换（可选，额度不够再用）

```bash
# .env 里：ACCOUNTS=.suno-profile-a,.suno-profile-b
npm run login:all          # 逐个登录（每个号一个窗口）
npm start -- --rotate
```

- **通过标准**：`login:all` 依次弹窗登录每个号；跑批时某个号额度耗尽，终端打印 `🔁 切换账号续跑`，自动用下一个号继续。
- **不通过**：
  - 切号没触发 → 确认额度耗尽时 SUNO 弹的文案被 `config.json` 的 `errorToast` 命中（含 credit/额度/insufficient 等）。
  - 某个号没登录上 → 单独 `USER_DATA_DIR=.suno-profile-b npm run login` 补登。

---

## 阶段 7 · 站内歌单归类（可选，best-effort）

```bash
npm start -- --playlist
```

- **通过标准**：生成完自动去 SUNO 资料库，把歌加进对应歌单，终端 `🗂 已加入歌单「xxx」`。
- **不通过**：这块最依赖页面结构，很可能要校准。`npm run inspect` 进资料库页，按阶段 3 的套路更新 `config.json` 里 `selectors.playlist.*`（`libraryUrl`/`search`/`rowByTitle`/`rowMenu`/`addToPlaylist`/`playlistOption`）。**失效不影响生成/下载**，本地歌单索引 `var/playlists.md` 照常生成，也可退回手动加。

---

## 阶段 8 · 网页面板 & 每日定时（长期挂机）

```bash
npm run panel -- --download --quality      # 浏览器开 http://localhost:8787 控制
node src/scheduler.js --now --download --quality   # 立即跑一轮，之后每天 DAILY_AT 自动跑
```

- **通过标准**：
  - 面板：`localhost:8787` 能看到进度条/当前歌/日志，暂停/继续/跳过/停止按钮有效。
  - 定时：打印 `下次运行：…（N 分钟后）`；到点自动跑。`DAILY_LIMIT` 限每天首数。
- **不通过**：面板打不开 → 换 `PANEL_PORT`；定时不触发 → 确认进程一直开着（`node`/`npm` 别关，Ctrl+C 会退出）。

## 常见问题速查

| 现象 | 多半是 | 去哪修 |
|---|---|---|
| 找不到某输入框/按钮 | SUNO 改版 | `config.json` 对应字段选择器（`npm run inspect` 看真实属性） |
| 歌词没结构标签/质量差 | 模型偏弱 | `.env` 换 `LLM_MODEL_DEFAULT` |
| 下载不到音频 | 接口形态变了 | `harvest.js` 接口过滤；或手动下 |
| 站内歌单加不进去 | 资料库页结构 | `config.json` 的 `selectors.playlist.*` |
| 判定「未确认提交」 | 成功/失败文案变了 | `config.json` 的 `errorToast` |
| 重复生成同一首 | 删过 `var/results.jsonl` | 保留该文件即可断点续跑 |

## 安全与合规提醒

- 只跑**你自己的** SUNO 账号，遵守 SUNO 服务条款与额度规则。
- 节奏别调太激进（`BETWEEN_SONGS_MS` 默认 45s + 抖动）。
- `.env`、`.suno-profile*/`、`var/` 都在 `.gitignore` 里，不会误提交登录态和 key。
