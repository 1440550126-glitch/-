# 攻击面测绘 · Attack Surface Mapping

漏洞不在「一行坏代码」里，而在**信任边界**上——数据从「不可信」被当成「可信」的那条线。测绘的目标就是把这些线全部标出来。

## 一、先建入口清单（Sources —— 攻击者能控制的一切）

别只盯着显式的 HTTP 参数。可控输入远比想象的多：

| 类别 | 常被忽略的具体入口 |
|---|---|
| HTTP | query、body、路径参数、**header**（`X-Forwarded-For`、`Host`、`Referer`、`User-Agent`、`Content-Type`）、**cookie**、multipart 文件名与内容 |
| 实时/推送 | WebSocket 帧、SSE 订阅参数、长轮询 |
| 回调 | 支付回调、OAuth `code`/`state`、Webhook（微信/短信/第三方）——**这些常被默认「可信」而漏校验签名** |
| 存储回流 | 从 DB / 缓存 / 文件读回并使用的数据（二阶注入、存储型 XSS 的源头） |
| 带外 | 上传文件的元数据/EXIF、导入的 CSV/JSON/XML、二维码/深链参数、剪贴板 |
| 内部 | 定时任务读取的外部数据、消息队列、环境变量（若被上游污染）、文件名本身 |
| 客户端 | `postMessage`、`location.hash`、`localStorage`、深链/scheme（小程序 `onLoad(options)`） |

**判据**：只要一个值*可能*被外部影响，它就是 source，无论中间转了几手。

## 二、再建汇聚点清单（Sinks —— 危险操作）

数据流到这些地方就可能出事：

- **DB**：SQL/NoSQL 查询构造（拼接=红灯）
- **Shell / 进程**：`exec`、`spawn`、`system`、反引号、`child_process`
- **文件系统**：`readFile`/`writeFile`/`unlink`/`createReadStream` + 用户可控路径 → 路径穿越/任意读写
- **HTTP 客户端**：`fetch`/`axios`/`request` + 用户可控 URL → SSRF
- **反序列化 / 解析**：`JSON.parse` 后合并对象（原型链污染）、`eval`、`Function`、YAML/XML 解析、`vm`
- **渲染 / 模板**：`innerHTML`、`dangerouslySetInnerHTML`、模板引擎插值、`v-html`、拼 HTML 字符串
- **鉴权判定点**：`if (user.isAdmin)`、`verifyToken`、权限中间件——**判定逻辑本身就是汇聚点**
- **加密 / 随机**：`Math.random()` 当 token、弱哈希、硬编码 IV/密钥、`==` 比对签名（时序侧信道）
- **重定向 / 响应头**：`Location`、`Set-Cookie`、CORS 头基于用户输入

## 三、把 source 连到 sink（Taint Tracing）

这是核心动作。对每个 sink，反向回溯：**喂给它的数据，最初来自哪个 source？中途有没有被有效净化？**

- 有效净化 = 参数化查询、白名单校验、类型强制转换、正确转义、框架自带防护。
- 无效净化 = 黑名单过滤（可绕）、只在前端校验、`replace` 一次（可双写绕过）、`try/catch` 吞异常当「处理了」。

追踪时读全链路：跨函数、跨文件、跨中间件。**大多数真实漏洞是「每一步单看都合理，连起来就破」**。

## 四、非常规攻击面（「不拘一格」的加分项）

清单式审计到此为止，高手从这里开始：

1. **报错与调试信息**：栈回溯、SQL 报错、`debug=true`、源码映射（sourcemap）、`/health`/`/metrics`/`/actuator` 暴露内部信息。
2. **竞态与并发**：TOCTOU（检查与使用之间的窗口）、余额/库存/配额/优惠券的并发扣减、验证码/token 一码多用、双花。
3. **状态机跳步**：多步流程（注册→验证→激活、下单→支付→发货、审核→发布）能否跳过中间校验直达终态？直接调后面那个接口试试。
4. **数值边界**：负数量、0、超大值、浮点精度、整数溢出、`parseInt` 截断、金额单位（分/元）混用、数组下标越界。
5. **批量赋值 / 参数污染**：请求体多塞一个字段（`isAdmin:true`、`role`、`balance`、`price`）会不会被整体接收写库？同名参数出现两次（HPP）时框架取哪个？
6. **默认值与配置**：默认口令、默认密钥、`.env.example` 里的真密钥、CI 配置里的凭据、`NODE_ENV` 未设导致跑在 dev 模式、CORS `*` + 携带凭据。
7. **文件相关**：上传的路径/扩展名/`Content-Type` 是否可控 → 覆盖任意文件 / 上传可执行文件 / 解析歧义；ZIP 解压穿越（zip slip）；软链接。
8. **缓存与多租户**：缓存键漏了用户维度 → 越权拿到别人缓存；CDN/代理缓存了带凭据的响应。
9. **信息不对称**：错误消息区分「用户不存在 vs 密码错」→ 用户枚举；响应时间差异 → 侧信道。
10. **第三方信任**：把回调/webhook 当可信而不验签；SSO/OAuth 的 `redirect_uri`、`state`、`nonce` 校验缺失；JWT `alg:none` / 弱密钥 / 不校验签名。
11. **供应链**：可疑 `postinstall` 脚本、依赖拉私有源、锁文件缺失导致漂移、typosquatting 包名。
12. **隐藏/遗留入口**：注释掉但仍可达的路由、`/debug`、`/test`、老版本 API（`/v1` 未下线）、备份文件（`.bak`、`~`、`.swp`）、`.git` 目录暴露。

## 五、按角色重走一遍

同一套代码，换个身份视角就有新洞：
- **匿名用户**：哪些接口不需要登录？其中哪些*本不该*匿名可达？
- **低权用户**：能不能碰到高权功能/数据？
- **越权到别人**：把资源 ID 换成别人的会怎样？
- **被封禁/已注销用户**：token 还有效吗？
- **多租户**：租户 A 能看到租户 B 吗？

把「这个功能给谁用」和「这个功能实际拦住了谁」对齐——差集就是越权漏洞。
